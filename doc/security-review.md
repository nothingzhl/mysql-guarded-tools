# 安全审查与验证记录

候选版本：0.7.0-rc.1。基线：此前本机使用的 0.6.0。审查范围是该连接器源码与发布包，不包含远端数据库权限审计或独立渗透测试。

## 已修复

| 问题 | 处理 | 证据 |
| --- | --- | --- |
| 密码通过 security 子进程参数传递 | Security.framework Swift helper；秘密只通过 stdin 管道传入 | security-regressions 的 argv/stdin/错误信息断言；本机编译通过 |
| 普通保存失败后钥匙串已修改 | 恢复旧密码，新增失败删除新增密码；复制先取值再统一保存 | 新增、编辑、复制、删除的磁盘失败回归 |
| 多进程配置覆盖 | 写操作持有独占 lock；配置随机临时文件原子替换 | 两个 ConfigStore 实例并发测试 |
| 密码曾经经 MCP 表单传递 | 删除该分支，统一原生隐藏输入 | native-password 测试；原生脚本编译检查，不实际弹框 |
| MCP 自定义服务未执行入参字段/类型检查 | 每次 tool 调用按声明约束验证，拒绝未知密码字段 | 协议与窗口边界测试 |
| 配置列表读取全部密码值 | 新 helper 只查询存在性 | keychain.has 优先使用断言 |
| 默认端口缺省时密码复制误拒绝 | 先规范化端口再比较账号身份 | 复制失败/回滚用例覆盖默认端口 |
| 非事务表不能可靠回滚，触发器可能有额外副作用 | 事务中持有元数据锁，限定 InnoDB 单表且证明触发器可见并确认为零；无法证明则拒绝 | 非事务引擎、视图、别名、多表、触发器及元数据不可见拒绝测试 |
| 原生密码脚本命令被换行拆断 | 单条 dialog 命令后再取返回值 | macOS osacompile 编译通过 |
| 刷新配置窗口丢失 token | sessionStorage 仅当前标签页保留 | 源码核对；尚未完成浏览器交互验收 |
| 保存成功、连接池刷新失败却报告失败 | 保存结果返回 runtime_warning | 模拟刷新失败测试 |

## 验证边界

- 本地隔离测试通过，详见 release-preparation 的最终数字。
- macOS 钥匙串 helper 编译成功；未在用户真实钥匙串新增、改密或删除任何条目。
- 未实际打开新版本密码弹框，未执行新版本真实数据库查询/UPDATE。
- npm 依赖审计未报告已知漏洞；这不能替代代码审计，也不保证不存在未知漏洞。
- 发布包不包含个人连接文件、旧窗口令牌、node_modules 或本机编译产物；启发式扫描通过。
- 旧版正在运行的配置窗口未被替换。本候选版本需要单独安装验收。

## 尚有的风险与发布条件

1. 钥匙串与 JSON 的跨存储崩溃一致性无法保证；普通异常回滚失败时需人工核对。
2. 同用户进程、调试器及浏览器扩展不在密码与窗口 token 的隔离保证内。
3. Swift helper 未签名、公证；首次访问钥匙串的提示和现有条目迁移需人工验证。
4. SQL 过滤不是完整解析器，仍需最小权限数据库账号及目标版本集成验收。
5. 多进程的运行时连接池不会自动同步；不与旧版同时编辑配置。
6. GitHub CI 仅已编写、未在远端运行。公共发布前须通过新机器安装及手工密码流程验收。
